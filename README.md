## 1. Описание

Консольная программа (CLI), похожая на терминал Linux.
Пользователь вводит команды, программа их выполняет и показывает результат.
В приглашении к вводу написано имя VFS: `[demo]$ `.

Написано на Java (нужен JDK 17 или новее).

### Этапы

- **Этап 1. REPL** — консольный диалог с пользователем, разбор команд
  с кавычками, сообщения об ошибках, команды-заглушки `ls` и `cd`,
  команда `exit`.
- **Этап 2. Конфигурация** — настройки запуска (`--vfs`, `--script`),
  вывод настроек при запуске, стартовый скрипт с комментариями.

Файл VFS на этом этапе ещё не читается (это будет в этапе 3): путь
только выводится в настройках, а из имени файла берётся имя для приглашения.

## 2. Команды и настройки

### Команды

| Команда | Что делает |
|---|---|
| `ls` | выводит своё имя и аргументы |
| `cd` | выводит своё имя и аргументы |
| `exit` | закрывает программу (с аргументами — ошибка) |

Аргументы с пробелами можно писать в кавычках: `cd "My Documents"`.
Внутри `"..."` работают `\"` и `\\`, внутри `'...'` всё берётся как есть,
пустой аргумент пишется как `""`.

Если команда неизвестна или кавычка не закрыта, программа пишет ошибку
и продолжает работать.

### Настройки запуска

| Параметр | Что задаёт |
|---|---|
| `--vfs ПУТЬ` | путь к файлу VFS (его имя без расширения видно в приглашении: `demo.json` → `[demo]$`; если не задан, имя — `vfs`) |
| `--script ФАЙЛ` | стартовый скрипт, который выполнится сразу после запуска |

Можно писать и так: `--vfs=ПУТЬ`. Неизвестный параметр, повтор параметра
или параметр без значения — ошибка (код возврата 2).

При запуске программа печатает все настройки (строки `[debug]`).

Стартовый скрипт — это текстовый файл, одна команда в строке.
Строки, начинающиеся с `//`, — комментарии (так же можно писать
комментарий в конце строки). Пустые строки пропускаются. Команды из
скрипта выводятся на экран вместе с результатом, как будто их вводит
пользователь. Если команда в скрипте с ошибкой, программа показывает
ошибку и идёт дальше. Если в скрипте есть `exit`, программа закрывается,
иначе после скрипта можно вводить команды вручную. Если файл скрипта
не найден, программа пишет ошибку и завершается с кодом 1.
Примеры скриптов лежат в папке `examples`.

## 3. Запуск и тесты

```bash
./run.sh                    # запуск программы
make test                   # запуск тестов
./run.sh --vfs examples/demo.json --script examples/startup.emu
```

Через make: `make run ARGS="--vfs examples/demo.json"`.

Готовые скрипты для проверки настроек: `scripts/demo_*.sh`,
например `bash scripts/demo_basic.sh`.

## 4. Пример

```
$ ./run.sh --vfs examples/demo.json
[debug] --vfs = examples/demo.json
[debug] --script = <not set>
[debug] vfs name = demo
[demo]$ ls -l "My Documents"
ls: ["-l", "My Documents"]
[demo]$ cd "oops
error: unterminated double quote
[demo]$ foo
foo: command not found
[demo]$ exit
```

Запуск со стартовым скриптом:

```
$ ./run.sh --vfs examples/demo.json --script examples/startup.emu
[debug] --vfs = examples/demo.json
[debug] --script = examples/startup.emu
[debug] vfs name = demo
[demo]$ ls
ls: []
[demo]$ cd /home/user
cd: ["/home/user"]
[demo]$ exit
```

Пример ошибки в параметрах:

```
$ ./run.sh --verbose
error: unknown option: --verbose
usage: emulator [--vfs <path>] [--script <path>]
```
